品質管理部が PR #31 の検証中に、`INSTAGRAM_LOGOS`(公式Instagramプロフィール画像の自サイト保存)の件数が、当初想定していた範囲(14店)を超えて26店まで増えていたことを検出した。リスクの**質**は当初と同一(公式アカウントのプロフィール画像のみ・店名ロゴのみ採用・出典明記・削除依頼フォーム稼働・`onerror` フォールバックあり)で、変わったのは**件数のみ**だが、無制限に広がることを防ぐ歯止めが無かった。

そこで**運用ルールを明文化し、上限を仕組みで担保する**方針とした(社長承認済み。承認の経緯は会社側の非公開記録に保管し、本ログと公開READMEには運用ルールのみを記載する)。

### 運用ルール(5項目)

| # | 内容 |
|---|---|
| 1 | **対象**は各店の**公式アカウントのプロフィール画像**に限る。アカウント同定の根拠を本ログに必ず記録する |
| 2 | **採用するのは店名ロゴ・店名グラフィックのみ**。人物写真・自撮り・料理写真・別店のロゴは採用しない |
| 3 | **件数上限は40件**(公開店舗数の25%相当)。上限到達時は自動継続せず改めて判断する |
| 4 | **四半期ごと**に件数と採否基準の遵守を棚卸しする |
| 5 | 各店舗ページに**出典**(その店の公式Instagramへのリンク)と**削除依頼フォーム**への導線を表示し、依頼を受けたら速やかに削除する |

### 上限の機械的担保

ルール③を運用の心がけに委ねず、`scripts/build.js` に `INSTAGRAM_LOGOS_MAX = 40` を定義し、`INSTAGRAM_LOGOS` の件数が超過した場合は**ビルドを失敗させる**実装を入れた(上限超過時 exit code 1 を実測で確認)。「上限に達したら自動的に続けない」というルールの趣旨を、人が必ず判断する導線として固定するため。上限そのものを引き上げるには、この運用ルールの見直しを経る必要がある。

現況: **26件 / 上限40件**(残り14枠)。

### ルール②に照らした過去の判断の再確認

`bar-zetton` で確認した Instagram アカウントは、プロフィール画像が人物写真でありルール②(店名ロゴ・店名グラフィックのみ)を満たさないため不採用とした判断は、本ルールと整合する。
